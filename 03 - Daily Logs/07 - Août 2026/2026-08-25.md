## 🧠 Ce que j'ai appris

- **Un vault public doit tenir seul** : même si les repos code vivent à côté, la doc journey ne gagne rien à pointer vers des chemins inaccessibles — mieux vaut une formulation générique et des placeholders.
- **L'historique se migre, pas se réécrit** : uniformiser le format H1 sans toucher au corps des notes préserve le récit tout en rendant la navigation cohérente.
- **Baseline dev ≠ mesure prod** : le delta Before/After du README mélange deux causes — migration CSS et passage en build production. Le TBT dev (`next dev`) est artificiellement catastrophique ; une partie du saut 4 380 ms → 20 ms vient du mode de build, pas du CSS seul.
- **Signal migration CSS isolé (dev)** : la mesure intermédiaire fin avril (nettoyage partiel, toujours en dev) avait déjà poussé la Perf Desktop de 55 à ~87 — c'est la preuve la plus propre de l'impact Tailwind. Le saut 87 → 95 en passant en prod est plausiblement l'effet build (minification, tree-shaking).
- **Mobile plat = autre goulot** : Perf accueil 53 vs 55 baseline (dev → prod) — pas de gain mobile malgré le build prod. Le frein mobile n'est pas le CSS mais le JS main thread et le LCP images ; chantier de suivi identifié.
- **A11y à part** : 71 → 73 (+2) — pas une régression, mais pas un succès à mettre sur le même plan que la Perf Desktop.
